# 动画规格说明（ANIMATION_SPEC）

> 对应验收项：AC-023（动效语法与教学层完整）。

## 1. 本题结构与焦点

| 项目 | 内容 |
| --- | --- |
| 主数据结构 | 输入字符串字符序列，字符位置固定为 `x = 110 + 48*i, y = 185` |
| 辅助结构 | BFS 候选队列，使用 `createQueue`，固定 8 个槽位；候选 ID 由候选字符串确定 |
| 必须画出的标量 | 当前候选、删除层数、队列占用、答案集合 |
| 每步焦点上限 | 最多一个 `current`；比较输入括号时不超过两个 `compare` |
| 步骤总数 | 对默认样例逐层生成快照，目标不超过 40 步；按语义合并相邻的重复/无变化动作 |

## 2. 步骤规划表

| step | operation | 焦点元素 | 状态变化 | 解说要点 | 代码锚点 |
| --- | --- | --- | --- | --- | --- |
| 0 | init | 输入字符 | 创建输入与空队列 | BFS 从原串开始，删除层数为 0 | init |
| 1 | dequeue | 队首候选 | 队首从队列移出 | 每次只检查一个候选，保持同层顺序 | dequeue |
| 2 | visit | 候选括号 | 对候选做括号余额扫描 | 只有余额不为负且最终归零才有效 | validate |
| 3 | enqueue | 新候选 | 删除一个括号后入队 | 仅移除括号，字母不参与删除；visited 去重 | generate |
| 4 | done | 最短答案 | 标记答案并停止扩展 | 首个有解 BFS 层的全部结果就是最少删除解 | collect |

BFS 快照从具体输入计算：步骤中间会把候选逐字符扫描为独立 `read` 操作，每步同时标出当前候选与字符余额；前缀余额变负立即标记错误，扫描结束余额非零则解释未匹配左括号。之后逐个展示删除位置、生成的新候选与入队去重。回溯快照真实运行 DFS：先展示左右括号删除预算，再逐个字符记录删除分支、保留/配对分支、重复分支跳过、非法前缀剪枝及答案命中；每帧显示当前构造路径、剩余 L/R 删除预算与未匹配余额。为避免长输入淹没观众，最多记录 48 个教学关键帧，但完整执行搜索并收集所有答案。

## 3. 运动语法

| 变化 | 实现 | 时长（1x） | 缓动 |
| --- | --- | --- | --- |
| 入场 | keyed join 淡入/缩放 | 220ms | easeBackOut |
| 移动 | 稳定 ID 节点平移 | 360ms | easeCubicOut |
| 状态切换 | 固定语义状态 CSS | 240ms | ease |
| 退场 | `fadeOutAndRemove` | 180ms | easeCubicIn |
| 箭头 | 带动作文字的路径生长 | 420ms | easeCubicOut |

所有时长取自 `features/animation/motion.ts` 的 `MOTION`；倍速与 reduced-motion 由共享渲染器处理。

## 4. 状态图例

| 状态 | 含义 | 本题是否使用 |
| --- | --- | --- |
| `current` | 当前处理的队首候选 | 是 |
| `compare` | 当前扫描括号/相邻删除选择 | 是 |
| `visited` | 已检查候选/已处理字符 | 是 |
| `done` | 最短答案 | 是 |
| `path` | 最终答案路径 | 否 |
| `error` | 不合法候选 | 是 |

图例固定，颜色不是唯一状态信号；无紫色。

## 5. 辅助结构容器

| 项目 | 内容 |
| --- | --- |
| 容器类型 | BFS 队列 |
| 固定容量 | 8 个槽位；若候选前沿更大则保持前 8 个可视节点并在指标显示总候选数 |
| 元素顺序 | 队首→队尾 |
| 指针 | 队首、队尾 |
| 空状态文案 | 空队列 |
| 入/出方向 | 新候选从右侧入队，队首从左侧出队；箭头写 `enqueue` / `dequeue` 与候选摘要 |
| 布局 API | `createQueue`（`features/animation/structures.ts`） |

## 6. 箭头与标注

队列数据流箭头带 `enqueue <候选>` 或 `dequeue <候选>` 文案；解释性 callout 标出“当前删除层”和“最短答案”。标签由模板渲染器按目标节点计算偏移，层级为容器 < 边 < 箭头 < 节点 < 标签。

## 7. 布局与坐标

稳定布局要求：跨帧复用稳定 ID 与固定坐标规则，使用 keyed join，确保相邻步骤至少 60% 元素位置保持不变。画布优先分配空间并遵守下述空间预算。箭头与标注规范：所有数据流箭头有动作文字，标签解释对象或下一步。

- 逻辑画布 `1200×720`，字符序列按 `x = 110 + 48*i, y = 185` 水平排列；输入最多 20 个括号，超长字符序列按可用宽度缩放间距。
- 候选字符串以稳定的内容 ID 排列在队列固定槽位；队列泳道位于主字符串下方，二者间距至少 80px。
- 原字符节点 ID 为 `char-i`，候选 ID 为 `candidate-${encodedString}`；同一对象跨帧复用 ID 和结构坐标。
- 默认全览，不因步进重置用户缩放/平移。

## 8. 教学层与代码同步

每步都有 operation、独立 narration、`anchorIds`、变量旁注与快照指标（删除层、已检查数、答案数）。四种语言实现相同 BFS 逻辑，锚点分别对应初始化、出队、校验、生成、收集。

## 9. 无障碍

`prefers-reduced-motion: reduce` 时共享动画渲染器将 JS 时长置零，CSS 关闭过渡；步骤、状态、解说、图例、变量及代码高亮保持更新。

## 10. 验收清单

- [ ] 相邻步骤通过 keyed join 复用稳定 ID，位置不重排。
- [ ] BFS 队列使用有固定容量、槽位、计数、方向指针和空状态的容器。
- [ ] 每步只有单一语义焦点，解说不重复且描述原因/结果。
- [ ] 每条数据流箭头有语义文字；图例、操作徽标、指标常驻。
- [ ] 最短解通过完整 BFS 层保证，重复候选不会重复入队。
- [ ] 1x/3x、跳步、reduced-motion、四语言代码映射完成实测。
